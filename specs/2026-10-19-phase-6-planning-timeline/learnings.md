## Contract bounds and semantics

- Plans: 1–64 steps, unique ASCII IDs of 1–64 letters/digits/underscore/hyphen; titles trimmed 1–240 chars; up to 64 declared patterns per step, each 1–512 chars; verify command trimmed 1–4000 chars. Patterns use workspace-relative POSIX separators; absolute/drive/ADS/traversal/control forms are refused. Accepted records/progress are engine-owned, excluded from submission input.
- Settings: strict integer step threshold 1–64 (review at >=); file threshold 1–10000 (review at >); strict boolean deviation flag. Defaults 4/3/true. Fixed high-risk trigger is separate.
- Activity scope records have stable scope/parent/turn/step identity and agent/model attribution. Existing message/reasoning/tool events gain optional scope; unscoped old events remain valid. Plan/activity/delegate/summary/context/steering events are typed, generated from Python. Future `ui.render`/`test.result` stay reserved.
- Timings are persisted UTC event timestamps, including waits/downtime. Latest-request context occupancy is separate from cumulative usage. Affected summary message count may be unavailable; no invented count.
- Steering submission: client ID 1–64 safe characters, trimmed text 1–32000 chars, ordered run-owned queued/delivered/cancelled acknowledgement. Planned HTTP contract: authenticated POST `/runs/{id}/messages`; unknown run 404, terminal/conflicting duplicate 409, malformed input 422; identical duplicate returns the existing acknowledgement. Delivery belongs in a parent-only before-model state update with deterministic HumanMessage IDs, then durable checkpoint reconciliation. Never invoke a second graph or release the pre-tool mixed barrier.

## Step 2: implementation and integration

- `planning/policy.py` expands concrete existing targets, deduplicates literal new paths and overlaps, and marks missing/wide/limited/link-containing expansions uncertain. Enumeration is bounded at 10,000 inspected files; declared literals are bounded by the schema. `.git`/link directories are not traversed and conservatively make wildcard counts uncertain. Windows path comparison is case-insensitive. Existing jail limitations still apply.
- Plan revisions bind submission, effective settings, exact config bytes and concrete-file scope. `permissions/review.py` reconstructs proposed scope from engine-owned prior metadata and reviewed tool arguments; edited previews cannot edit scope metadata separately. Plan JSON changes appear alongside file diffs. The declared verification command is never run by submission/approval.
- `PermissionMiddleware.aafter_model` remains the single human barrier. It classifies effects against the *prior* accepted plan and active step, then applies allowed plan/progress updates only after all human requirements resolve. Same-turn plan adoption cannot authorize a previously denied sibling. Multiple plan/progress replacement calls in one turn are refused. Approval revisions are rechecked before adoption and ordinary journal/permission/jail checks remain in dispatch.
- `submit_plan` is a typed tool; `write_todos` uses `[stable_id] title`. Only one active parent, no pending-to-completed shortcut, no completed-history deletion and no active-to-pending rewrite. Structural todo changes return proposals and use the deviation gate. The progress adapter takes running child step IDs; actual child lifecycle wiring follows in Step 3.
- Deviation baselines survive automatically adopted incremental changes; the third cumulative new ID pauses in Ask/Auto. Explicitly reviewed changes reset the baseline. Renaming/reordering cannot hide scope/risk/verify changes. Automatic structural revisions remain labelled automatic even when an earlier revision was approved.
- `.harness/config.json` load/merge preserves unrelated keys and refuses malformed files. Authenticated GET/PUT `/planning/settings` uses the existing durable configuration approval ledger. Saves always review, including Auto; exact bytes/revision are checked, a snapshot precedes the atomic write, and direct snapshot revert is blocked. No key/model is needed to review configuration.
- Default/general-purpose and unknown delegate names are refused at the parent permission boundary. Step 3 will replace the stock task middleware with the proved compiled reviewer/researcher configuration; no delegate receives authority from a plan approval.
- Demo edit and mixed question/effect scenarios now submit and activate a real plan before their original effect. Legacy permission/recovery fixtures do the same through actual tool calls, retaining original effect IDs. Their assertions continue checking original effects and independent barriers rather than counting new planning bookkeeping as effect dispatch.
- Existing completed/uncertain effect journal entries are returned before new-plan checks, preserving readable older recovery results without dispatching anything. New unclassified effects fail closed.
- Evidence: full combined backend suite **387 passed in 279.88 s**; after private-state/dispatch tightening, **19** affected real-graph tests and **28** policy/config/progress tests passed.
