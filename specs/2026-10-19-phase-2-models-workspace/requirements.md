# Phase 2: Models and Workspace. Requirements

Status: **Approved by the user on 2026-10-19; local implementation complete, live validation pending.**

## Goal
A user can add and test models with their own keys, pick a safe workspace, and start a task from Home, preserving the offline demo and Phase 1 guarantees.

## In scope
Settings shell, Models and keys, add/edit dialog, language switch, provider adapters and probes, safeStorage keys, context detection, reasoning events, token meter, workspace recents/task list, Home, and relevant empty/error states.

## Out of scope
New execution tools, permission enforcement/editor, approvals, planning, skills, branch switching, worktree creation, workspace file browser, real context ring/compaction, other Appearance functionality, schedules and installers.

## Sources and decisions
- Constitution: `specs/mission.md`, `tech-stack.md`, `roadmap.md`, `challenge-traceability.md`; Phase 1 validation/handoff; phase prompt and `prompts/00-kickoff.md`.
- Visual source: `Home.dc.html`, `Settings.dc.html`, `SettingsAddModel.dc.html`, `SettingsAppearance.dc.html`, `Empty.dc.html`, `Errors.dc.html` under `docs/mock-source/`, plus `docs/design-tokens.md`.
- Explicit phase restrictions apply to future controls drawn in the mock: Jev/Metis presets and Worktree disabled; context ring a placeholder; Appearance language only. Mock providers, keys, counts, branch names and context sizes are illustrative, not seeded data or verified API facts.
- No constitution amendment is proposed. Jev/Metis URLs remain unknown. Web search is outside this phase.

## Functional requirements
- **R1 — Settings.** Open Settings from the pinned gear. Render seven sections in mock order: Models and keys; Appearance and language; Permissions and safety; Context and compaction; Terminal and tests; Data and privacy; About. Only models and language function; remaining sections visibly indicate deferred functionality.
- **R2 — Records and cards.** Persist nonsecret provider metadata, stable IDs and default selection in app data outside workspaces. Show name, URL, model, auto-detected context, key status masked to at most four trailing characters, probe status, default chip, Test and Edit. Add/edit/default survive restart. Always list the keyless offline demo; never seed fictitious cloud records. A successfully tested provider can be selected/defaulted.
- **R3 — Dialog.** Match the rounded 620px dialog, dim backdrop, Persian copy, helper text and Cancel/Test connection/Save actions. Inputs: display name, Base URL, password API key, exact model name. No price, context or kind input. Presets directly below URL come from `backend/providers/presets.json`: OpenAI `https://api.openai.com/v1`, Anthropic `https://api.anthropic.com`, AvalAI `https://api.avalai.ir/v1`; Jev/Metis have null URLs, disabled buttons and accessible `URL pending` tooltips. Validate required fields/URL. Editing may retain a key without returning plaintext to the renderer.
- **R4 — Adapters and run selection.** Anthropic preset or exact parsed hostname `api.anthropic.com` infers native Anthropic; other accepted endpoints infer OpenAI-compatible. Lookalike hostnames do not select Anthropic. Use verified installed `langchain-openai`/`langchain-anthropic` APIs. Resolve runs by provider ID, reject unknown/unusable providers, and snapshot configuration for an active run so edits do not alter it.
- **R5 — Secrets.** Electron main owns safeStorage encryption/decryption. Only encrypted keys and opaque references persist in app data; engine receives plaintext in memory. Never return stored plaintext to the renderer or put keys in URLs, arguments, workspace files, checkpoints, events, logs, errors or child environments. Fail closed when encryption/decryption fails. Key retention/replacement must not create plaintext fallback files. Clear transient dialog keys on close/save. Retire automatic Phase 1 external credential-file loading in the product path; never silently import or modify that external file. Canary tests cover success and failure flows.
- **R6 — Probe and errors.** Connection test performs a tiny schema-defined tool-call probe without filesystem/command effects. Require a valid structured call and arguments, not advertised capability or text. Unsupported providers remain editable but cannot run/default. Untested metadata can be saved; successful testing is required before use. URL/model/key edits invalidate success. Map 401, 429 and no-tool support to the exact relevant Persian mock messages/actions and English equivalents. Interpret max 3 tries as **three total attempts**, with automatic backoff/retry state and no multiplying SDK retries. Sanitize other failures. The mock's no-file-changes assurance applies to the probe, not arbitrary runs that already did work.
- **R7 — Context.** Resolve in order: matching model metadata from the provider models endpoint; sourced built-in `backend/providers/context_table.json`; safely parsed context-length error; conservative 32,768 marked `~`. Persist source/estimated status. Missing/failing metadata must not fail a valid tool probe. Reject malformed/nonpositive limits; never invent metadata fields or send huge requests to force errors. Refresh on test or relevant runtime error. Demo displays `—` per mock.
- **R8 — Reasoning.** Preserve actual returned Anthropic thinking and OpenAI-compatible `reasoning_content` through provider-aware conversion; emit redacted `reasoning.delta` separately from ordinary output. Handle string/structured chunks without duplication. Test both adapters with deterministic fixtures; record per live provider/model whether reasoning arrived, was unsupported, or unverified. Do not infer reasoning from answer text. Phase 6 timeline remains deferred.
- **R9 — Tokens.** Emit `usage.updated` and show cumulative per-run tokens from reported input/output usage; otherwise use a documented estimate marked `~`. Include tool turns; avoid double counting streaming/final usage, reset on new run, reproduce through replay/reconnect. No monetary values. Home context ring is static and labeled as a placeholder without fabricated live percentages.
- **R10 — Workspace safety.** Native picker cancellation preserves selection. Canonicalize and reject drive/UNC share roots, actual user home, aliases/junctions to forbidden targets, files and inaccessible/missing folders. Enforce independently in Electron and engine direct run requests. Persist deduplicated recent paths/names and selection in app data; stale entries recover without running. Preserve Phase 1 jail and its documented alias/race limitations.
- **R11 — Tasks and branch.** Sidebar workspaces expand to real task titles/status. Persist an app-data task index and reopen recorded output by replaying the selected workspace's jailed event log; never rerun automatically. Read branch metadata without executing repository code: ordinary `.git/HEAD`, gitdir files and detached HEAD; hide branch outside git. No branch switching; Worktree disabled with Phase 3 tooltip. No fictitious tasks or approval badges.
- **R12 — Home.** Match greeting `ایده‌ها را به کد تبدیل کن`, quick-start chips, large composer and exact Persian placeholder, model selector/send, second bar with workspace, branch, Worktree and permission mode. Chips fill editable task text; grill-me does not execute a skill. Record Read-only/Ask/Auto selection (Ask default), retaining the existing read-only tool surface in every mode; permission UI/enforcement remains Phase 3. Preserve health gating, Stop, ordered SSE and OpenUI output.
- **R13 — Empty states.** No selected workspace shows the mock's no-workspace state and working folder picker. No selected usable model shows no-model state with Add model and Use demo model actions; demo remains available without forcing selection. Submission requires both prerequisites. If sample-project action is drawn, explicitly defer it instead of leaving an inert enabled button.
- **R14 — Language/accessibility.** Persian RTL/dark on fresh profile. Settings > Appearance switches Persian/English immediately and persists across restart. Preserve mock Persian strings, Persian UI digits, LTR paths/model IDs, logical CSS, tokens, 240px sidebar and inset 24px surface. Dialog/dropdown names, keyboard navigation, focus containment/return and Escape work; disabled-control tooltips have focusable wrappers. Components delegate business logic to stores/services. Other Appearance controls are deferred.

## Quality and exit requirements
- **R15.** Every automated acceptance item is executable and manual items need observed evidence. Run ruff, strict mypy, pytest, TypeScript, UI tests, static build and Windows desktop checks. Verify real OpenAI-compatible and native Anthropic tool runs using credentials outside the workspace; missing access leaves checks open and phase incomplete. Record verified APIs/versions, context table sources, reasoning results, deviations and TODOs in `learnings.md`. Commit after each approved plan step. Propose any constitution/roadmap amendment and get approval before editing it.
